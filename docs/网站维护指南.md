# MSB 网站维护指南（管理员版）

> 本文汇总网站所有常见维护操作。**成员自助改个人信息**请看 [成员自助维护指南.md](成员自助维护指南.md)。
> 一句话原则：**所有内容都是仓库里的文件，改文件 → 提交 → 1~2 分钟自动上线，没有后台、不需要登录任何管理系统。**

---

## 一、网站是怎么工作的（30 秒版）

- 网站 = 仓库里的一堆静态文件（HTML/CSS/JS/JSON/图片），托管在 GitHub Pages，地址 https://yun-shuang.github.io
- 你每次把修改**提交/合并到 `main` 分支**（网页上改、本地 push、合并 PR 都算），GitHub 的免费机器人（Actions）就会自动构建并发布
- 时间线：提交 → 约 10 秒机器人启动 → 约 30~60 秒构建部署 → 全球生效。**总共约 1~2 分钟**
- 查看进度：仓库页面顶部 **Actions** 标签，绿色勾 = 成功，红色叉 = 失败（会收到邮件）
- 浏览器有缓存时按 **Ctrl + F5** 强制刷新看最新版

两种改法，效果一样：

| 方式 | 适合 | 操作 |
|---|---|---|
| GitHub 网页直接改（推荐日常用） | 改文字、上传照片 | 仓库 → 点开文件 → ✏️ 编辑 / Add file 上传 → Commit changes |
| 本地改完 push | 批量改动、结构调整 | 改文件 → `git add -A && git commit -m "..." && git push` |

## 三、研究方向（首页列表 + 研究页详情）

首页与研究页由**同一份** `_data/research.json` 驱动，分工不同：

- **首页**：只显示 4 个方向名（每行可点击，跳到研究页对应锚点 `#slug`）
- **研究页**：显示完整内容 —— 标题、描述、关键词要点、代表论文、该方向成员

每个方向的字段：

| 字段 | 说明 |
|---|---|
| `slug` | 锚点 id（英文短横线），首页跳转用，改了这个要一致 |
| `title` / `title_zh` | 方向名（中英） |
| `desc` / `desc_zh` | 一段描述（中英） |
| `points` / `points_zh` | 关键词要点数组（显示为标签），可留空 |
| `members` | 成员 id 数组（对应 `_data/members/<id>.json` 的 `id`），决定研究页"团队成员"栏 |
| `papers` | 代表性论文明细数组（`title`/`venue`/`year`/`link`），**可留空** |
| `ongoing` | 可选，`true` 时在该方向显示"相关研究进行中"小字 |

**降级规则**：`papers` 为空则不显示"代表性论文"栏目（不会出现空白标题）；若想说明在做但还没发文，把 `ongoing` 设为 `true`。
**显示上限**：每个方向最多显示 3 篇代表论文，超出部分显示"更多论文 →"引导到学术成果页；研究页顶部有 4 个方向的锚点导航，方便跳转。

成员 id 规则：英文姓名转小写、空格换连字符（名-姓顺序），例如 `Xiaoxue Fu` → `xiaoxue-fu`。
调整某人归属方向，只需在对应方向的 `members` 数组里增删该 id（不用改成员文件）。

## 四、成员信息

- 成员自助：打开 **https://yun-shuang.github.io/member-json/** 填表 → 下载 `<id>.json` → 按 [成员自助维护指南.md](成员自助维护指南.md) 提 PR，管理员审批合并
- 管理员代改：直接编辑 `_data/members/<id>.json` 提交
- 成员照片：传到 `assets/people/<id>.jpg`（**正方形，边长 ≥400px，≤300KB**），在成员 json 里把 `photo` 填为该路径；不填则显示姓名首字母头像
- 毕业/离组：把 `role` 改为 `"alumni"`，可选填 `destination`（去向）

### 权限说明

- 普通成员：**不需要任何权限**，网页提 PR 即可（GitHub 会自动 fork）
- 管理员（能审批 PR、直接提交）：仓库 **Settings → Collaborators → Add people** 邀请其 GitHub 账号（Write 权限），并把用户名加入 `.github/CODEOWNERS`（每行一个 `/_data/members/ @用户名`）

## 五、活动相册（团队成员页轮播）

> 照片自动显示在**团队成员页底部的"活动掠影"轮播**（自动播放、底部圆点手动切换、鼠标悬停暂停、手机可左右滑动），无需单独维护展示。

**加照片**：仓库 → `assets/img/gallery/` → Add file → Upload files → 提交。机器人会自动把新照片追加进 `_data/gallery.json` 并发布，**不用改任何代码**。
**删照片**：删除文件夹里对应文件并提交，机器人会自动移除清单条目。
**加说明文字**：编辑 `_data/gallery.json`，找到对应条目填 `caption`（英文）/`caption_zh`（中文）；数组顺序 = 显示顺序。

**图片规格建议**：宽度 1200~2000px，JPG/PNG/WebP，**单张 ≤ 500KB**（手机原图 3~15MB 必须先压缩）；建议横版（轮播按 3:2 裁切）。

## 六、首页"近期研究文章"封面图

- 论文条目在 `_data/highlights.json`（标题、作者、期刊、引用数、`link` 跳转链接）
- 封面图放到 `assets/img/covers/`，命名 `paper-1.jpg` ~ `paper-5.jpg`（与条目里的 `cover` 字段一一对应）
- **缺图不会报错**：会自动显示一张"期刊名 + 标题"的文字卡片，所以可以随时补图

## 七、论文列表同步

- **自动**：每周一凌晨（UTC 02:00）从 OpenAlex 同步樊老师的论文、引用数、h 指数
- **手动**：仓库 → Actions → 左侧 "Sync Publications" → 右侧 "Run workflow"
- **失败怎么办**：机器人会邮件通知；下周会自动重试；急需可本地跑 `python scripts/sync_publications.py` 后提交
- 数据源说明：用 OpenAlex 而非 Google Scholar，因为 Google 会拦截云端抓取（详见 README）

## 八、常见问题

**Q: 改完多久能看到？**
一般 1~2 分钟。成员/相册类改动多一步机器人自动汇总（约 +30 秒）。先在 Actions 标签确认绿色勾，再 Ctrl+F5 刷新页面。

**Q: F5 和 Ctrl+F5 有什么区别？**
- **F5**（普通刷新）：浏览器尽量用本地缓存，可能仍显示旧版本；
- **Ctrl+F5**（强制刷新，等价 Ctrl+Shift+R）：跳过浏览器本地缓存，重新下载全部文件——确认"网站更新了没有"时用它。
- 注意它只清理你自己浏览器的缓存；GitHub 的 CDN 缓存通常几分钟内也会自动更新。

**Q: 网页上找不到 ✏️ 编辑按钮？**
确认你登录的是有权限的 GitHub 账号（管理员）；普通成员请走 PR 流程（见成员指南）。

**Q: 改错了能恢复吗？**
能。Git 保存全部历史：仓库 → 文件 → History 可查看并回退任何版本。

**Q: 想在首页加新板块 / 大改样式？**
属于结构性修改，建议本地改完充分预览（`python -m http.server 8000`）再 push，或交给维护者处理。
